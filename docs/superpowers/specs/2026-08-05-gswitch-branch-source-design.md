# gswitch 分支来源标识设计

## 目标

`gswitch` 的交互菜单必须明确区分本地分支与已获取的远端追踪分支，避免用户误以为列表中的所有分支都在本地。

## 范围

仅调整无参 `gswitch` 的交互菜单和它写给 PowerShell 包装函数的选择结果。带参数的 `gswitch <branch>` 与参数补全行为不变。

## 菜单规则

- 每个本地分支显示为 `[本地] <branch>`；当前分支额外保留 `*` 标识并排在本地列表首位。
- 每个远端追踪分支显示为 `[远端] <remote>/<branch>`；忽略 `<remote>/HEAD`。
- 本地与远端同名时仍显示两项，不合并也不隐藏。
- 顺序为全部本地分支在前、全部远端追踪分支在后；各自按不区分大小写排序。
- 菜单只读取本地已有的 Git 引用，不自动执行 `git fetch`。因此“远端”表示最近一次获取到本地的远端追踪引用。

## 选择与切换

Python 脚本把“来源 + Git 引用”写入临时文件，PowerShell 包装函数据此执行切换。

- 选择本地项：执行 `git switch <branch>`。
- 选择仅存在于远端的项：执行 `git switch --track <remote>/<branch>`，创建并切换到跟踪分支。
- 选择已有同名本地分支的远端项：执行 `git switch <branch>`，复用现有本地分支，不创建重复分支。
- 无法解析或切换失败时由 Git 返回错误；临时文件仍在 `finally` 中删除。

## 验证

- 为 Python 分支分类和选择结果增加单元测试，覆盖本地、远端、同名和 `origin/HEAD`。
- 在 Git 仓库中手动验证菜单标签和远端独有分支的跟踪切换。
- 运行现有 `gswitch` 相关测试及 PowerShell 语法解析。
