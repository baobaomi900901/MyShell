# reloadsh 终端重开保护

## 目标

终端启动失败、启动结果不确定或用户取消时，保留当前 PowerShell 会话。仅在用户确认新终端正常打开后返回退出码 43，由 PowerShell 包装函数关闭旧会话。

## 行为

- 保留函数索引扫描、macOS 加载流程和 `--no-restart`。
- Windows 完成扫描后提示“函数索引已更新”，避免声称当前会话已重新加载函数。
- Tabby 可执行文件依次从 PATH、LOCALAPPDATA、ProgramFiles、ProgramFiles(x86) 查找；找不到时输出明确错误并返回 10。
- 启动参数使用列表传递，保留包含空格的目录。
- 启动进程的 stdin 使用 DEVNULL；stdout/stderr 写入临时文件，避免后台进程长时间持有管道或大量日志导致死锁。
- 等待最多 3 秒观察启动结果。非零退出码或日志中的明确异常（例如 uncaughtException、TypeError、FATAL）按失败处理，即使退出码为 0 也不能忽略异常。
- 仍在运行只表示启动请求已提交，不终止该进程，也不声称新标签页已打开。扫描观察期内捕获的完整日志，显示的诊断输出限制为末尾 8 KiB；读取不改变后台进程的文件位置。
- Tabby、Windows Terminal 和 VS Code 都在请求发出后询问是否确认新终端正常打开；默认不关闭。False、None、Ctrl+C 都保留当前会话。
- PowerShell 包装函数检查 Python 是否可用，捕获调用异常，避免使用上次命令遗留的退出码；只有 Python 返回 43 才关闭终端。

## 取舍

仅检测进程状态不能证明标签页可用；自动握手需要修改终端配置或 profile。采用启动诊断加用户确认，覆盖当前故障并保持改动范围集中。

## 验证

使用真实 Python 子进程验证非零退出、退出 0 但输出异常、普通弃用警告、大量输出及保持运行的进程；用边界替身验证终端路径及交互取消；在独立 PowerShell 子进程中验证包装函数退出码行为。测试不会打开真实终端或关闭用户会话。
